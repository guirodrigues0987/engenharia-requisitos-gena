# Requisitos Funcionais — Sistema Eventus

Extraídos a partir das falas registradas no documento de elicitação (seção 3 — Informações Obtidas nas Entrevistas). Cada requisito referencia o stakeholder de origem.

| ID | Requisito Funcional | Origem |
|----|----------------------|--------|
| RF-01 | O sistema deve permitir que o participante visualize todos os eventos disponíveis em um único lugar (catálogo de eventos). | Participante |
| RF-02 | O sistema deve emitir um comprovante de inscrição logo após a inscrição do participante ser realizada. | Participante |
| RF-03 | O sistema deve permitir que o participante cancele sua própria inscrição, sem necessidade de contato com a organização, quando o evento permitir cancelamento. | Participante |
| RF-04 | O sistema deve permitir que o participante emita seu certificado após o evento. | Participante |
| RF-05 | O sistema deve permitir que o participante se inscreva em múltiplas atividades/workshops, impedindo inscrição em atividades com horários conflitantes. | Participante / Organizador |
| RF-06 | O sistema deve permitir que o organizador crie e configure eventos e atividades. | Organizador |
| RF-07 | O sistema deve controlar automaticamente o número de vagas disponíveis por evento/atividade. | Organizador |
| RF-08 | O sistema deve criar e gerenciar uma lista de espera quando um evento/atividade atingir o limite de vagas. | Organizador |
| RF-09 | O sistema deve permitir que o organizador defina, por evento, se o cancelamento de inscrição é permitido. | Organizador |
| RF-10 | O sistema deve exibir ao organizador a quantidade de inscritos em tempo real. | Organizador |
| RF-11 | O sistema deve permitir que o organizador gerencie os participantes inscritos em seus eventos. | Organizador |
| RF-12 | O sistema deve permitir à equipe financeira confirmar pagamentos de inscrições pagas. | Equipe Financeira |
| RF-13 | O sistema deve condicionar a liberação de determinadas inscrições à confirmação do pagamento. | Equipe Financeira |
| RF-14 | O sistema deve permitir à equipe financeira registrar/processar reembolsos, nos casos em que o participante tiver direito. | Equipe Financeira |
| RF-15 | O sistema deve permitir que o palestrante consulte a programação de suas atividades. | Palestrante |
| RF-16 | O sistema deve permitir que o palestrante consulte a lista de participantes inscritos em suas atividades. | Palestrante |

> **Observação:** RF-16 tem escopo de dados pendente — o material de elicitação não define quais informações do participante podem ser exibidas ao palestrante (ver `lacunas-e-ambiguidades.md`, L-08).
