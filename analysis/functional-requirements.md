# Functional Requirements - Eventus System

Extracted from the statements recorded in the elicitation document (section 3 - Information Obtained in the Interviews). Each requirement references its source stakeholder.

| ID | Functional Requirement | Source |
|----|------------------------|--------|
| FR-01 | The system must let participants see all available events in a single place (event catalog). | Participant |
| FR-02 | The system must issue a registration receipt right after the participant's registration is completed. | Participant |
| FR-03 | The system must let participants cancel their own registration, without contacting the organization, when the event allows cancellation. | Participant |
| FR-04 | The system must let participants issue their certificate after the event. | Participant |
| FR-05 | The system must let participants register for multiple activities/workshops, preventing registration in activities with conflicting schedules. | Participant / Organizer |
| FR-06 | The system must let the organizer create and configure events and activities. | Organizer |
| FR-07 | The system must automatically track the number of available spots per event/activity. | Organizer |
| FR-08 | The system must create and manage a waitlist when an event/activity reaches its spot limit. | Organizer |
| FR-09 | The system must let the organizer define, per event, whether registration cancellation is allowed. | Organizer |
| FR-10 | The system must show the organizer the number of registered participants in real time. | Organizer |
| FR-11 | The system must let the organizer manage the participants registered in their events. | Organizer |
| FR-12 | The system must let the finance team confirm payments for paid registrations. | Finance team |
| FR-13 | The system must make the release of certain registrations conditional on payment confirmation. | Finance team |
| FR-14 | The system must let the finance team record/process refunds in cases where the participant is entitled to one. | Finance team |
| FR-15 | The system must let the speaker view the schedule of their activities. | Speaker |
| FR-16 | The system must let the speaker view the list of participants registered in their activities. | Speaker |

> **Note:** FR-16 has a pending data scope - the elicitation material does not define which participant information may be shown to the speaker (see `gaps-and-ambiguities.md`, G-08).
