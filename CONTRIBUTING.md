# Contributing

## Workflow

1. Create a branch from `main` (`docs/...`, `fix/...`).
2. Make small, focused commits.
3. Open a pull request and fill in the template.

## Commit messages

This project follows [Conventional Commits](https://www.conventionalcommits.org/), written in English:

```
<type>(<optional scope>): <short imperative summary>
```

Common types: `docs`, `fix`, `chore`.

## Writing conventions

- Keep identifiers stable: FR (functional requirement), BR (business rule), G (gap), A (ambiguity), UC (use case), US (user story).
- Never fill an open point with an assumption: mark it `[OPEN POINT]` or `[TO VALIDATE]` and reference the gap.
- Documentation is written in English.
